# Разработка

Текущая версия — `v0.3.0`, 29 сентября 2026 года; исходная публичная версия — `v0.1.0`. Рабочие инструкции находятся в `skills/zodchiy`; документация сопровождения и материалы проверки остаются за пределами устанавливаемой папки.

| Файл | Назначение |
|---|---|
| `skills/zodchiy/SKILL.md` | Условия применения, основной процесс и выбор справочника |
| `skills/zodchiy/agents/openai.yaml` | Метаданные отображения |
| `references/workspaces.md` | Рабочие поверхности и состояние действий |
| `references/explanation.md` | Раскрытие сложного материала и доказательств |
| `references/reading.md` | Чтение, ссылки и сохранение контекста |
| `references/visual-direction.md` | Визуальные ориентиры и сравнение результата |
| `references/learning.md` | Основания решений и границы выводов |
| `references/catalog.md` | Выбор слоя и направления; алиасы и совместимость |
| `references/air-constructivism.md`, `presence-gouache.md`, `material-presence.md` | Авторские карточки, загружаемые отдельно |
| `data/profiles.json` | Единый источник пяти тем, двух шрифтовых профилей, семантических ролей и печатной палитры |
| `scripts/validate.py` | Структура, ссылки, бюджет ядра и числовые профили |

Пути `references/*` и `data/*` в таблице указаны относительно `skills/zodchiy`.

## Ограничения содержания

Ядро `SKILL.md` — не более **702 слов, разделённых пробельными символами**, включая frontmatter. Это верхняя граница, а не целевой объём. Справочники загружаются по задаче; обязательное чтение всех файлов увеличивает нагрузку и нарушает устройство пакета.

Перед добавлением правила проверить, не содержится ли оно уже в ядре или справочнике. Сохранять одно место для каждого положения. Дополнение справочника не должно становиться способом скрыто увеличить обязательную работу.

В публичный пакет не включать личные данные, внутренние материалы, закрытые ссылки и персональные кейсы, в том числе пересказанные с заменёнными именами. Формулировать метод непосредственно, без истории частного проекта.

## Проверка изменений

Из корня репозитория выполнить:

```bash
python3 scripts/validate.py
```

После этого прочитать diff, проверить соответствие метаданных инструкциям и доступность затронутых относительных ссылок. В описании изменения указать фактически выполненные проверки и их ограничения. Статический валидатор не оценивает удобство интерфейсов; статус доказательств описан в [evaluation.md](evaluation.md).

## Организация каталога 0.3.0

Из Pro Max взяты принципы раздельного обращения к направлениям, цвету и типографике, совместимости выбранных слоёв и сохранения общего решения с локальными исключениями. Основания: [search.py](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/09170eec67eefd46a7ae85de61b40c194020f997/src/ui-ux-pro-max/scripts/search.py) и [design_system.py](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/09170eec67eefd46a7ae85de61b40c194020f997/src/ui-ux-pro-max/scripts/design_system.py). Код, CSV, отраслевые соответствия и чужие дизайн-профили не копировались.

Данные — собственные авторские профили: Material Presence v0.2 r1, редакционные семейства шрифтов и отдельный печатный вариант. Они описывают средства дизайна без частных историй, фотографий и предметных данных. Шрифтовые файлы и внешние художественные произведения не включены. Исходный эталон Style 04 отсутствует в поставке.

Для этого объёма достаточно Markdown-индекса: поиск по имени или задаче, затем выбранная карточка и нужная запись JSON. Исполняемый поисковик, BM25 и генератор CSS не добавлены. Пять тем светлые; редакционный профиль задаёт семейства и наследует масштабы проекта.

При изменении JSON обновлять существующую версию профиля осознанно. Валидатор проверяет роли, HEX, алиасы действий и 64 указанные непрозрачные пары: 60 внутри пяти тем и четыре пары статусов. Это не полная проверка всех возможных сочетаний или соответствия приложения стандарту доступности. Для новых свойств расширять проверку только под конкретный риск.
